# 4단계 — [For Demo] 인가·판정 검증 (툴을 믿기 전에 툴을 시험)

> 실물 칩 + SPI/I2C 장비 대신 DUT RTL 시뮬레이션에 변환 벡터를 인가해 확인

## 입력
- 2단계 결과: 테스트벡터 생성 코드, 판정 코드

## AI 역할
- 판정 코드 초안 (기대값과 실측값 비교, 리포트 출력)

## 사람이 확인한 것
| 확인 | 방법 | 결과 |
|---|---|---|
| 정상 조건에서 전부 PASS | 실제 칩 순서로 실행 | 139/139 PASS |
| 틀린 조건에서 FAIL을 잡는가 | 사양서 순서(big)로 little 칩 시험 | 115/139, 16비트 레지스터만 FAIL → 원인 위치가 정확히 드러남 |
| 두 실행 경로의 결과가 같은가 | RTL 시뮬레이션 vs Python 모델 | 139개 항목 판정 동일 |
| 다른 IP에도 재사용되는가 | VDDI-200(big-endian, I2C 주소 0x3D)으로 같은 템플릿 실행 | 139/139 PASS |
| 인터페이스만 바꿔도 같은가 | 같은 IP를 SPI / I2C로 각각 실행 | 판정 동일 |
| I2C 주소 오류를 잡는가 | 틀린 장치 주소로 실행 | NACK 표시, ID 확인 단계에서 원인 안내 |
| 사람이 정한 기대값 반영 | 기대값을 직접 지정(값/이미지) 후 재실행 | 지정한 기준으로 판정, 출처 '지정' 표시 |
